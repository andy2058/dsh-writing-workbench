# Cover Master（封面生成专家）

## 核心规则
本技能是「封面生成工作流」，不是风格所有者。流程：从内置风格库中选定**恰好一个**风格，再把该风格原子编译进封面形态。
最终图片提示词不是「封面指令 + 风格指令」的松散拼接，而是一条完整、集成、面向封面的生成提示词。
三个输入：
1. 任务字段：平台、画幅比例、标题提炼、文章摘要、封面传达目标、通用输出约束。
2. 选定风格的 `references/styles/{style-id}.md`（含结构化元数据 + 可复用视觉原子）。
3. `references/cover-prompt-blueprint.md`（封面提示词的完整结构）。
风格文件定义可复用的视觉语言，蓝图定义输出形态，最终提示词必须把两者融合成一条完整提示词。

## 资源
- `references/style-catalog.md`：17 个风格目录与推荐规则；选风格前阅读。
- `references/cover-prompt-blueprint.md`：最终提示词的必需结构；编译提示词前阅读。
- `references/styles/{style-id}.md`：选定风格后阅读对应文件（内含 YAML 元数据 + 视觉风格原子正文）。
- 风格库来源：参考 https://github.com/adrianpunk/Punk-Skill 的 punk-cover 风格体系（致谢 @adrianpunk）。

## 工作流

### 1. 分析源内容
- 提取核心视觉主体；保留用户完整标题或主题，但不把文章正文复制进任何输出字段。
- 按需拟一条可选副标题（风格有副标题字段时）。
- 长文转成精简派生字段：标题/主题、1-3 句语境摘要、视觉主体、受众、情绪、隐喻、禁用元素。

### 2. 确认平台与画幅（生成任何提示词之前）
- 小红书：`3:4`；微信公众号：`2.35:1`；X / Twitter：`5:2`。
- 自定义：严格保留用户比例。
- 用户只给源内容时，必须询问发布平台，此时不生成提示词。
- 用户给了自定义比例，直接使用，除非措辞需要平台信息，否则不再问平台。
- 用户给精确宽×高（无比例）时，推导并保留该比例；显式尺寸与显式比例冲突时，先问哪个为准。
- 默认生成单张图。用户明确要求多尺寸套图时，保留每个目标比例，且至少两个目标才生成。
- 多尺寸套图禁止用裁切、拉伸、补边或拼格满足；每个目标比例单独编译一条独立构图的提示词。
- 仅当用户已提供平台/比例，或明确说全权自动决定时，才跳过此问题。

### 3. 确认风格（生成任何提示词之前）
- 用户指定了目录中的某个风格，直接用。
- 用户提供了与某风格匹配的完整视觉方向（如「超大标题 × 中央主体 × 图文穿插」「真实纸雕层叠 × 极简留白 × 柔和光影 × 准确隐喻」「抽象概念 → 游戏机制 → 像素关卡世界」「OSB 木板 × 工业蓝标识字 × 极简线条隐喻」等），视为已指定该风格，不再追问。
- 未指定风格时：根据内容推荐恰好 3 个目录风格，各给一句贴合内容的理由，请用户选择或给出自定义方向。
- 除非用户要看全菜单，否则默认不展示全部风格。
- 只有用户明确说「全自动」时才自动选风格；仅提供了文章不等于可以自动选。

### 4. 确认闸门
- 平台/比例或风格缺失时，问完问题即停。不填写风格文件、不保存提示词、不生成图片。
- 只给文章的首次回复 = 平台问题 + 3 个推荐风格（见「首次回复格式」）。
- 平台/比例与风格都已知时，直接继续，不再询问。

### 5. 编译最终提示词
- 按 `references/cover-prompt-blueprint.md` 的必需结构编译。
- 只读一个选定风格的 `references/styles/{style-id}.md`，取其 `style_anchors`、`cover_shape_adaptation`、`must_preserve`、`avoid_when_applying_to_cover` 与风格正文中的不可妥协锚点（材质、空间逻辑、标题处理、字体行为、纹理、配色、风格特有禁用项）。
- 把任务字段与风格锚点融合成一条完整提示词，读起来像完整的封面生成 brief，而不是两段无关提示词拼贴。
- 提示词包含封面形态各节：角色/任务、输入字段、内容理解、标题层级、封面构图、风格落地、图文关系、字体、色彩/材质/纹理、负面约束、最终标准。
- 每个封面决策都必须通过选定风格表达。例如风格是手撕拼贴，标题、主体、辅助文字、背景、隐喻都要用手撕纸、旧报纸、胶带、颗粒、网点、纸层实现，而不是「普通封面 + 拼贴字样」。
- 禁止把风格文件原文作为独立第二段粘贴；把风格原子改写、适配进蓝图。
- 禁止组合多个风格，禁止加第二个自定义风格段。
- 替换或消解所有 `{{...}}` 占位符；长文只用精简派生字段填标题/主题区；不要把文章正文贴进最终提示词。
- 多尺寸套图：每个目标比例单独编译一份蓝图，内容、隐喻、风格身份、材质、配色保持一致，构图、尺度、字体、留白、阅读方向、空间行为按比例重写。

### 6. 生成前保存提示词文件
- 单张图：创建 `cover-assets/{slug}/prompts/cover.md`，写入完整填充后的提示词。
- 多尺寸套图：每个目标一个文件 `cover-assets/{slug}/prompts/cover-{ratio-or-size}.md`（用文件系统安全的比例/尺寸标签）。
- slug 用主题词的简短拼音/英文/数字标识，不要用会话 ID。

### 7. 生成图片
- 本环境有 `image_gen` 工具时，默认在保存提示词后生成一张图片。多尺寸套图时每个目标独立生成一张。
- 生成时遵守 image_gen 的工具约束：
  - **提示词里要生成的所有文字（主标题、副标题、标签等）必须用中文引号「“”」标注**，不可使用其他符号。
  - 按画幅比例换算 width/height（默认 2048 边长），例如 3:4 → 约 1536×2048 或 2048×2730；2.35:1 → 约 2048×872；5:2 → 约 2048×819；比例不符时优先保证目标比例。
- 仅在用户明确要求 prompt-only（只要提示词），或环境没有图像生成工具时，跳过生成。
- 图像生成工具返回了可检索的当前产物时，保存为 `cover-assets/{slug}/cover.png`；不要靠扫描大目录猜产物；工具只返回内联预览、无当前轮可检索产物时，不伪造 cover.png。
- 工具不可用时，返回提示词文件路径与完整提示词内容。

### 8. 交付
- 生成成功后将最终封面图通过 `present_files` 交付给用户；同时给出 `cover-assets/{slug}/prompts/cover.md` 路径。
- 如果用户要求多尺寸套图，逐张交付，不要合并为拼图。

## 首次回复格式（只给文章、无平台无风格时）
简洁提问：
1. 目标平台 / 画幅？
   - 小红书：`3:4`
   - 微信公众号：`2.35:1`
   - X / Twitter：`5:2`
   - 自定义：给出比例
2. 推荐风格（各一句贴合文章的理由）：
   - `风格A`：理由
   - `风格B`：理由
   - `风格C`：理由
结尾请用户选择平台与一个风格，或回复「自动」由技能全权决定。

- 搭建 / 团队 / 计划 / 教育 / 系统隐喻：`积木世界`、`方块世界`（若库中有）。

- 视频封面 / 科技解说 / 高冲突社媒：`复古日本科幻动画`（若库中有）、`黑红剪影`。
- 不要推荐库中不存在的风格；菜单只列 `references/styles/` 下实际存在的文件。

## 输出纪律
- 最终提示词必须是一条由任务字段 + 蓝图 + 恰好一个选定风格融合而成的完整封面提示词。
- 不把风格文件原文作为独立第二段粘贴。
- 不把长文正文贴进最终提示词，只用摘要与派生字段。
- 提示词文件内不写风格选择理由。
- 不组合多个风格，不追加第二个自定义风格段。
- 默认一张输出；只有用户明确要求多尺寸套图才生成多张，且每个比例独立构图、独立产物。
- 中文标题必须准确、可读：不写错字、不裁切、不遮挡到不可识别。
- 通用封面失败项必须规避：PPT 封面感、课程封面感、通用信息图模板、电商广告感、无关装饰、标题缺失/拼错/被严重遮挡。
